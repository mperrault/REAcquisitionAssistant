# Vision

## Product name

RE Acquisition Assistant

## Vision statement

Create a private, configurable real-estate acquisition decision-support system that helps a buyer identify unusually attractive properties, evaluate them consistently, document why they were accepted or rejected, and make better acquisition decisions over time.

The product is not intended to replace listing portals. Listing portals are optimized for discovery. RE Acquisition Assistant is optimized for **judgment, ranking, comparison, due diligence, and institutional memory**.

## Initial user problem

The initial user is searching for a second home but is dissatisfied with the quality of conventional inventory. The preferred strategy is to acquire a dated or cosmetically undesirable home on an exceptional property and perform a moderate renovation.

The challenge is not merely finding houses that meet bedroom and price filters. It is finding homes with scarce attributes such as:

- country or mountain views
- open fields / pastoral setting
- horse-property character
- small-farm character
- river frontage
- water views
- New England character
- strong resale appeal

The application should reduce the need to repeatedly sift through hundreds of listings and should help distinguish a mediocre house on a great property from a great-looking house on an ordinary property.

## Product principles

### 1. Setting first

Land characteristics and setting can be difficult or impossible to create later. Cosmetic house defects can often be corrected. The system should therefore allow setting and resale attributes to outweigh interior finishes.

### 2. Configurable preferences

No acquisition preference should be permanently hardcoded. Towns, ranking weights, budgets, drive-time thresholds, deal breakers, renovation tolerance, house-style preferences, and feature priorities must be configurable.

### 3. Facts are separate from opinions

Property records store observed or sourced facts. Search profiles contain preference and scoring logic. The same property may score differently under different profiles.

### 4. Explainability

Every score should be explainable. Users should be able to see:

- positive contributors
- penalties
- hard-filter failures
- missing information
- confidence in the score

### 5. Learn from decisions

The product should retain rejection reasons, visit notes, offer history, and user overrides. These records can later help detect patterns and improve the scoring model.

### 6. Generic engine, specific profiles

The initial profile is a Quiet Corner second-home search. The software itself should be generic enough to support future searches such as:

- retirement home
- investment property
- vacation rental
- waterfront home
- downsizing
- another geographic region

## Success criteria

The product is successful when it helps the user answer these questions quickly:

- Which new property is worth seeing?
- Why does this property rank highly?
- Is this property better than one we previously rejected?
- What will the total project cost likely be?
- Does the setting justify renovating the house?
- What are the risks or deal breakers?
- What did we learn from the last 20 properties?
